THE SYMPTOMS, UP CLOSE

  • Mystery suffixes — files ending in _OL that only their maker can decode.

HOW IT GOT THIS WAY — MY BEST READ

Nobody did anything wrong here. The Drive is basically a record of how the team grew. The agency set up the first structure — logos, fonts, social. Then the creative side came on and built their own corners, then engineering, then music, then AR. Every new person brought their own habits and made their own folders, because there was nothing telling them where things go. And when two people needed to trade files quickly, they made a folder named after themselves, which works perfectly for those two people that week. A couple of years of that and you get what's there now: several different ways of writing a version number, finished pieces sitting next to their own drafts, and files that only make sense to whoever put them there.

Why it keeps happening: every new collaborator, vendor, and launch adds folders faster than anyone cleans them up. The real cost isn't tidiness — it's time lost hunting for finals, the risk of a printer getting sent a superseded file, and the fact that when someone moves on, their filing system goes with them. Cleaning it up once buys a few weeks. The gap is structural: there's nothing that decides where a finished file goes, and nobody whose job it is to care.

HOW IT WORKS DAY TO DAY

  • The dashboard — every commissioned piece and its 0–5/5 delivery status, on one page.
  • Commission a piece — title, product, design; the piece gets its own delivery page.
  • The upload page — five slots per piece: image, printable PDF, hi‑res video, low‑res video, QR. Drag a file in and it's named by the convention automatically and stored in the archive. Re‑uploading a slot creates v02 and retires v01.
  • Share links — any delivered file copies a 7‑day expiring download link for vendors and printers. No login on their end.

Filenames are generated server-side, so nothing can be mislabeled on the way in, and multi‑GB videos upload in chunks without drama. The passphrase above signs you in for 30 days; vendor links bypass it by design. If the team grows, the gate upgrades to per‑person email sign‑in without touching anything else.

THE NAMING STANDARD

The Worker names files automatically. This is the same system written down for humans — the convention every deliverable follows wherever it's saved, built on the pattern the product spec files already use, tightened.

The rule underneath it: the PD is the single source of truth. Every product, print, design, and colorway gets its canonical name from the PD. If a name isn't in the PD, it doesn't go on a file — it gets added to the PD first, then the file gets named. Renames happen in the PD first, then propagate.

THE PATTERN Theria_<Product>_<Design>_<Colorway>_<vNN>_<TYPE>.<ext> Theria_WaterCarafe_Eden_v06_MASTER.ai Theria_Candle_Hands_LtPurple_v01_PRINT.pdf Theria_Placemat_Eden_v03_TARGET.png Theria_Jug_Peacock_v02_SOC-9x16.mp4
Product
PascalCase, from the PD — WaterCarafe, CoffeeCup, TrayLarge, Candle, BakingDishOval
Design
the print or artwork, from the PD — Eden, Hands, Peacock, Leopard, Jellyfish, Vines, Dragon, Lion
Colorway
only when variants exist — LtPurple, DkPurple
vNN
always lowercase v + two digits: v01, v06. Never V5, never "final", never "(1)"
TYPE
what the file is for — it retires the mystery suffixes
MASTER
layered working file — .ai, .aep, .prproj, .psd
OL
outlined / flattened print-ready vector
PRINT
print-ready export, with dimensions — PRINT-14x20
TARGET
AR image target
AR
AR video or experience asset, with platform — AR-zappar, AR-snap
WEB · SOC
website / social exports, with ratio where relevant — SOC-9x16
SHOT
photography — product or lifestyle

ONE TREE, SEVEN RULES

One tree in the shared Theria folder, organized by print first — that's how the brand thinks. The underscore prefix marks a standard folder and sorts it to the top; DJ's existing _category template keeps working inside each print.

Theria/
  _BRAND/      logos, fonts, brand docs, comp research
  _PD/         the source-of-truth database + product/packaging specs
  PRINTS/      one folder per PD design — Eden/, Hands/, Teapot/ …
               inside each: _masters · _images · _movs · _outputs · _AR
  PRODUCTS/    per-product print-ready files — what vendors receive
  PHOTO/       shoots by date — 2026-07_ProductShoot/
  MARKETING/   social, website, presentations, catalog
  MUSIC/
  _ARCHIVE/    superseded versions, old shoots — never delete, archive
  _INBOX/      drop zone for anything unsorted — see rule 03

Person-named folders go away: their contents get filed by design and product, and the empty shells get archived.

THE SEVEN RULES — EVERY COLLABORATOR

  1. Name at export, from the PD. Check the PD for the canonical name before saving. Not in the PD? Ping the PD owner to add it — don't invent one. No final, new, copy, (1), or camera filenames in shared folders.
  2. One current version, visible. When a new version is approved, the old one moves to _ARCHIVE/ under the same subpath. A folder never shows two versions of the same asset — history within a file is Drive's job; history across exports is v##'s.
  3. The _INBOX rule. Not sure where something goes? Drop it in _INBOX/ with a correct filename — never into a random folder. One person empties it weekly.
  4. Masters live in Drive; apps work locally. Working files (.aep, .prproj) are edited locally, and the saved master is pushed to the print's _masters at each milestone. Auto-save, cache, preview, and render-scratch folders stay out of Drive sync — they're what's polluting it today.
  5. Personal My Drives are drafts only. Anything others need moves to the shared tree the day it's approved. If it's not in the shared Theria folder, it doesn't exist for the team.
  6. Handoffs are folders, not files. Printers, Zappar, retailers get a dated folder in PRODUCTS or the print's _outputs — 2026-08_ZapparHandoff/ — never loose files in chat or email.
  7. Access hygiene. Folder ownership consolidated; new collaborators get folder-level access, not file links. Shortcuts to external docs get replaced with real shared copies.

THE ROLLOUT — ONE PRINT AT A TIME

  1. Lock the PD. Confirm the product and design lists are complete and the names final — that's the ask in section 06.
  2. Build the empty tree in the shared folder, with the existing folder-structure template inside PRINTS/.
  3. Pilot one print end-to-end — Eden, the most active — fixing names as files move.
  4. Bulk-pass the rest. Everything ambiguous goes to _INBOX; everything superseded goes to _ARCHIVE.
  5. Sweep the personal folders — theria_allen, theria_eden, Dj&Allen, For Dave… — into the tree.
  6. Circulate the rules. Each collaborator confirms; this document lives in _BRAND/ as the standing reference.
